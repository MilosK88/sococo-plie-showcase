# SYSTEM DIRECTIVE: LuKul Atelier Churn Reactivation Engine (CRE)

## 1. Project Overview

This is a B2B SaaS product targeted at Premium Fitness Centers in the EU/Serbian market.
It is an asynchronous data pipeline that ingests cold archival gym data (CSV), scores members mathematically based on historical behavioral telemetry, and uses an LLM to generate hyper-personalized, localized outreach messages.

## 2. Tech Stack

- **Backend:** Python 3.11+, FastAPI, PostgreSQL, Redis, `uv` for package management.
- **Frontend:** Next.js (App Router), React, Tailwind CSS.
- **Infrastructure:** Docker Compose (local development).

## 3. Architectural Invariants (DO NOT DEVIATE)

1. **No External Orchestrators:** We do not use n8n or Zapier for internal routing. Orchestration is done natively in Python using `asyncio`.
2. **Strict Idempotency:** Every webhook and CSV ingestion MUST use a Redis NX lock to prevent duplicate processing.
3. **Relational Data Only:** Use PostgreSQL. Do not suggest MongoDB or NoSQL. Gyms, members, and scores are strictly relational.
4. **Decoupled State:** The backend API and Next.js frontend are completely separate. The frontend only communicates via REST endpoints.

## 4. Language & Localization Rules

- **Code & Comments:** English.
- **LLM Prompt Generation:** The output generated by OpenAI MUST be strictly in the **Serbian ekavica** dialect (e.g., "ovde", "promena", "menjati"). Ijekavica ("ovdje", "promjena") is strictly forbidden.
- **Future-proofing:** The system must use a `TenantContext` to allow future switching of the LLM prompt language (German, French, English) without altering the Python scoring logic.

## 5. Development Workflow

- Always write explicit types in Python (`def process(data: dict) -> list:`).
- Always use Pydantic for data validation.
- Keep the `api` layer (routers) completely separate from the `services` layer (business logic).
